# Предложение по анимации: «Единое окно»

## Принципы

1. **Анимация помогает читать страницу, а не украшает её.** Страницы раздела длинные и справочные: стипендии занимают почти 19 000px. Движение нужно, чтобы показать структуру (раздел → карточки → детали) и отметить, где пользователь находится. Оно не должно задерживать чтение.
2. **Коротко и один раз.** Появление при скролле длится 0,7–0,9 с и срабатывает один раз. При повторном проходе блоки больше не «прыгают».
3. **Только `transform` и `opacity`.** Эти свойства браузер анимирует на GPU. Раскладка страницы не пересчитывается, скролл не дёргается даже на слабых телефонах.
4. **Одна кривая на весь раздел:** `cubic-bezier(0.22, 1, 0.36, 1)` (ease-out-quint), быстрый старт и мягкая посадка. Единая кривая даёт ощущение одной системы.
5. **Без библиотек.** Всё сделано на CSS-переходах, `IntersectionObserver` и `requestAnimationFrame`. Код занимает около 9 КБ (`js/window.js`, без минификации), внешних зависимостей нет, нет риска конфликтов с CMS университета.
6. **Уважение к `prefers-reduced-motion`.** Об этом ниже, в отдельном разделе.

## Что и как анимируется

### 1. Первый экран

| Элемент | Анимация | Зачем |
|---------|----------|-------|
| Логотип, герб Минобрнауки, заголовок | Появление снизу вверх (20px → 0, opacity 0 → 1), 0,8–1 с, заголовок с задержкой 0,12 с | Мягкий вход вместо резкого появления контента |
| Линейный герб на фоне | Проявляется из `scale(1.06)` за 1,6–1,8 с. При скролле медленный параллакс со смещением 0,18 от скорости страницы | Добавляет глубину фону. Движение медленное и на заднем плане, поэтому не отвлекает от текста |
| Кнопка меню | Закреплена в углу. После ухода первого экрана из вида становится непрозрачной с тенью | Меню доступно на любой глубине длинной страницы |

### 2. Меню

Меню раскрывается кругом из кнопки-бургера (`clip-path: circle()`, 0,6–0,7 с). Пункты появляются «лесенкой» с шагом 40 мс. Три линии бургера превращаются в крестик. Такой переход связывает кнопку и меню: видно, откуда оно пришло и куда уйдёт. Закрыть меню можно по Esc, фокус возвращается на кнопку.

### 3. Появление блоков при скролле

Блоки контента выезжают на 28px и проявляются, когда на экран попадает 12% блока. У однотипных элементов в одной группе есть ступенчатая задержка 50–120 мс, чтобы группа читалась как одно целое:

- плитки услуг и плитки-якоря разделов (шаг 60–70 мс);
- карточки льготных категорий и документов (50 мс);
- списки прав, обязанностей и запретов (40 мс);
- строки таблицы условий кредита, ссылки-«пилюли», карточки PDF-документов.

Вариации по направлению подчёркивают композицию: заголовки групп выезжают слева, текст рядом с кругом «СТАВКА 3%» справа, сам круг появляется из `scale(0.85)`.

### 4. Акцентные анимации

| Где | Что | Зачем |
|-----|-----|-------|
| Общежитие → «Порядок заселения» | Вертикальная линия прорисовывается за скроллом (`scaleY` от прогресса прокрутки блока). Точки шагов «выщёлкиваются» с лёгким отскоком, когда линия до них дотягивается | Процесс из 5 шагов читается как последовательность. Пользователь видит, на каком шаге находится |
| Кредит → «Почему это выгодно» | Счётчик «0% → 3%» за 1,1 с (ease-out-cubic) при появлении круга | Выделяет главный аргумент страницы |
| Маскот-снежный барс (8 иллюстраций) | Появление «с пружиной» (подъём 60px + `scale(0.92)`, overshoot), затем медленное «дыхание»: смещение на 6px и наклон 0,6° с циклом 5 с. Цикл ставится на паузу, когда маскот вне экрана | Оживляет фирменного персонажа без отвлечения: амплитуда минимальная, CPU за пределами экрана не тратится |

### 5. Отклик на наведение и нажатие

- **Плитки услуг и разделов:** фон заливается снизу светло-синим (0,5 с), синий кружок увеличивается в 1,25 раза и в нём проявляется стрелка. Так плитка явно становится кнопкой.
- **Ссылки-«пилюли»:** инверсия цветов (синяя заливка, белый текст), стрелка поворачивается на 45°.
- **Карточки документов, адрес, карточки PDF:** подъём на 3–6px с усилением тени.
- **Кнопки «Узнать» и «Перейти»:** подъём на 2px и белое свечение-обводка.
- **Соцсети:** подъём на 4px и подсветка.
- **Ссылки в футере:** подчёркивание вырастает слева направо.

У всех интерактивных элементов есть видимый `:focus-visible` (жёлтая обводка), поэтому навигация с клавиатуры не хуже, чем мышью.

### 6. Карусель фото общежития

Кнопки «назад/вперёд» листают на одну фотографию с плавной прокруткой. На крайних позициях кнопки гаснут. На десктопе фото можно перетаскивать мышью с доводкой до ближайшего кадра, на телефоне работает нативный свайп с `scroll-snap`.

## `prefers-reduced-motion: reduce`

Если в системе включено «Уменьшить движение» (iOS, macOS, Windows, Android), сайт работает без анимации, но с тем же содержимым:

| Что | Поведение |
|-----|-----------|
| Появление блоков при скролле | Отключено, все блоки видны сразу |
| Вход первого экрана, проявление герба | Отключено, герб виден сразу |
| Параллакс герба | Отключён, слушатель скролла его не двигает |
| «Дыхание» маскотов | Отключено (`animation: none`) |
| Линия таймлайна заселения | Сразу нарисована целиком, все точки видны |
| Счётчик «3%» | Сразу показывает итоговое значение |
| Раскрытие меню кругом, лесенка пунктов | Меню появляется мгновенно |
| Плавная прокрутка по якорям и в карусели | Мгновенный переход (`scroll-behavior: auto`) |
| Hover-эффекты | Меняется только цвет, без перемещения и без переходов |

Если JavaScript в браузере отключён, всё содержимое тоже видно: скрытое состояние блоков навешивается только при наличии класса `.js` на `<html>`.

## Что можно добавить на следующем этапе

- **View Transitions API** для переходов между страницами раздела: плитка услуги «перетекает» в синюю плашку-заголовок открываемой страницы. Уже работает в Chrome и Edge, в остальных браузерах страница откроется обычным переходом.
- **Подсветка активного раздела** в плитках-якорях при скролле длинной страницы (стипендии, общежитие) через тот же `IntersectionObserver`.
- **Lottie-анимация маскота** (например, барс машет лапой в блоке «Контакты»), если дизайнер подготовит исходник. Сейчас маскоты растровые, поэтому анимируется только иллюстрация целиком.

Библиотеки вроде GSAP для текущего объёма не нужны. Их стоит подключать, только если появятся сложные таймлайны (сторителлинг, пиннинг секций).
